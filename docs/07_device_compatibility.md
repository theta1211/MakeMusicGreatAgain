# 07. 対応機種・対応キーボード方針

方針: **できるだけ多くの端末とキーボードで動かす**。動作を「保証する」範囲と「動く」範囲を分け、実機テストと自動テストを組み合わせて広げる。

## 1. OS バージョン

| 項目 | 値 | 理由 |
|---|---|---|
| **minSdk** | **24(Android 7.0)** | BLE-MIDI の標準 API は 23 から使えるが、Jetpack ライブラリの最低対応が 23 以上に上がりつつあり、23 を維持するコストが高い。24 なら利用中端末のほぼ全てをカバーできる |
| targetSdk | **36(Android 16)** | Google Play の要件(2026 年 8 月 31 日以降、新規アプリと更新は API 36 が必須) |
| 次の対応 | 37(Android 17) | 2027 年の Play 要件に合わせて更新 |

OS バージョン別の動作の違い:

| Android | API | 音声出力 | MIDI 受信 | Bluetooth 権限 |
|---|---|---|---|---|
| 7.0〜8.0 | 24〜26 | OpenSL ES(Oboe が自動選択) | Kotlin の `MidiReceiver` → JNI | 位置情報権限が必要 |
| 8.1〜9 | 27〜28 | AAudio | 同上 | 同上 |
| 10〜11 | 29〜30 | AAudio | **AMidi**(C++ 直接) | 同上 |
| 12 以降 | 31+ | AAudio | AMidi | `BLUETOOTH_SCAN` / `CONNECT`(位置情報不要) |

## 2. 端末の種類

| 種類 | 対応 | 備考 |
|---|---|---|
| スマートフォン | ◎ | 縦・横 |
| タブレット | ◎ | 横を主に設計 |
| 折りたたみ(縦折り / 横折り) | ◎ | 画面の展開・折りたたみで状態を保ったままレイアウトを切り替える。半開き時は上下分割 |
| Chromebook(Android アプリ対応機) | ○ | 物理キーボード・マウスでの操作に対応。ウィンドウのサイズ変更に追従 |
| Samsung DeX 等のデスクトップモード | ○ | 同上 |
| Amazon Fire タブレット | △ | Google Play 非対応。Amazon アプリストアでの配布を将来検討(Play Asset Delivery が使えないため別手段が必要) |
| Android TV / Wear OS / 車載 | × | 対象外 |
| CPU | arm64-v8a、armeabi-v7a(32bit 端末向け)、x86_64(Chromebook・エミュレーター) | 3 種類をビルド |

## 3. 性能ランク別の動作

性能は画面サイズではなく、起動時のベンチマークと機能フラグで判定する([仕様 8 章](03_specification.md#8-端末性能の自動判定))。

| ランク | 例 | 同時発音 | トラック上限 | エフェクト | 保証レベル |
|---|---|---|---|---|---|
| High | Pixel 8 以降、Galaxy S / Tab S 上位、Snapdragon 8 系 | 64 | 16 | 全部 | 保証 |
| Mid | Galaxy A5x、Pixel a シリーズ、Snapdragon 6/7 系 | 32 | 8 | 全部 | 保証 |
| Low | 2〜3 万円台以下、RAM 3〜4GB | 16 | 4〜8 | リバーブ簡易版 | 動作する(遅延が大きい可能性を表示) |
| Very Low | RAM 2GB 以下 | 8 | 4 | 最小限 | ベストエフォート |

### 4.2 自動テスト(台数を増やす)
- **Firebase Test Lab** で数十機種に対し、起動・画面遷移・オフラインレンダリング・ベンチマーク・クラッシュを確認する(音の遅延は測定できない)。
- エミュレーターで Compact / Medium / Expanded、折りたたみの各画面構成を UI テストする。

### 4.3 利用者からの情報収集(リリース後)
- アプリ内の「レイテンシ測定」結果を、ユーザーが任意で送信できる仕組み(オプトイン)を将来追加し、機種別の推奨設定表を作る。
- ストアのレビューと問い合わせから、相性問題を機種リストに追記する。

## 5. 対応キーボード

### 5.1 BLE-MIDI キーボード(楽器用)
BLE-MIDI は Apple が定めた仕様に沿った共通規格で、Android でも標準 API で接続できる。メーカーが「Android 対応」と明記していない機種も多いので、**実機で動作確認したものを「確認済み」として公開**する。

| 区分 | 例 | 備考 |
|---|---|---|
| 小型 MIDI キーボード | KORG microKEY Air(25 / 37 / 49 / 61 鍵)、Artesia / CME Xkey Air、M-VAVE 等の低価格 BLE 鍵盤 | microKEY Air は公式には iOS / Mac / Windows 向け表記。Android は要実機確認 |
| パッド系コントローラー | KORG nanoKEY Studio / nanoPAD 系(Bluetooth 対応モデル) | ドラムパッドとして使う |
| BT 対応の電子ピアノ・キーボード | Roland、Yamaha、Casio、KORG の Bluetooth MIDI 搭載モデル | 機種により BLE-MIDI と「Bluetooth オーディオのみ」のものがある。MIDI 対応を要確認 |
| **BLE-MIDI アダプター** | Yamaha MD-BT01 / UD-BT01、CME WIDI Master / WIDI Uhost 等 | **5 ピン MIDI や USB の既存キーボードを無線化できる**ため、対応できる鍵盤が一気に増える。推奨構成として案内する |

確認項目: 接続、自動再接続、ノートオン / オフ、ベロシティ、ピッチベンド、モジュレーション、サスティン、打鍵から発音までの遅延、30 分連続使用での切断有無。

### 5.2 USB-MIDI キーボード(有線、参考)
- USB-C(OTG)で接続。BLE より遅延が小さく安定しているので、「遅延が気になる場合の代替」として案内する。
- 一般的な USB クラスコンプライアント機器はドライバー不要で動く。

### 5.3 PC 用キーボード(Bluetooth HID)
- OS が標準で対応しているので、ほぼ全ての Bluetooth キーボードで動く。
- 配列の違い(JIS / US)を考慮し、**キーの位置(スキャンコード)で割り当て**、文字ではなく物理位置で判定する。
- テスト対象: Logicool 等の汎用 BT キーボード(JIS / US 各 1)、タブレット用カバーキーボード、Chromebook 内蔵キーボード。
- テキスト入力欄にフォーカスがある時は演奏用の割り当てを無効にする。

### 5.4 Bluetooth 音声出力(イヤホン・スピーカー)
- 演奏には不向き(150〜300ms の遅延)。接続を検知したら「遅延が大きいので有線イヤホンか本体スピーカーをおすすめします」と表示する。
- 再生だけ(作った曲を聴く)の場合は問題ないので、警告は演奏画面のみで出す。
